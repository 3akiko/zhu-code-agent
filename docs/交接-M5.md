## 1. M5 要做什么（roadmap 定义）

**M5 Agent 扩展：并行与 Subagents（P0）**——从"单 agent 串行"升级为"多 agent 并行"，技术说服力最强的里程碑，面试重点：
- ① **客户端并发安全重构**（**硬前置**，TODO 已记）：`AnthropicClient` / `OpenAiClient` 的流累积状态（inputTokens/outputTokens/stopReason/thinkingAccum/toolAccums 等）是实例字段，同一实例并发 `stream()` 有数据竞争。M1 靠「每轮新建实例 + UI 串行」规避；M5 做 Subagents/并行前须重构为 **per-call 状态持有者**（一个流一个状态对象，客户端实例可复用、可并发）。
- ② **并行工具执行**：读类并行 / 写类串行、结果保序（`ToolExecutor` 新增并行实现，**接口不变**，M2 就留了这个扩展点）。
- ③ **Subagents / Task**：父 agent 派生子任务（独立会话/权限/护栏上限），结果回填，支持并行子任务。
- **不做**：MCP/Hooks/Skills（M6）、OS 沙箱（M7）；`-p` 非交互与结构化输出容错后置 M8+（2026-08-10 范围调整）。
- 验收入口：M5 的 `docs/spec.md`（走 hdz-code-spec 四文档流程）。

## 2. 关键架构速查（M5 会动的部分）

```
Main
  ├─ llm/
  │     ├─ AnthropicClient / OpenAiClient   流累积状态为实例字段 → M5 ① 重构为 per-call 状态持有者（并发硬前置）
  │     ├─ AbstractStreamingClient           SSE 消费骨架；LlmStream（M4：事件队列 + cancel/join）是 per-call 句柄，天然适配状态持有者
  │     ├─ LlmClient / LlmClientFactory      stream(ChatRequest) 返回 LlmStream；工厂每轮 new 实例（M5 可改缓存复用）
  │     └─ StreamEvent                       StreamEnd(stopReason, in, out, cacheRead, cacheCreation)；密封事件模型
  ├─ agent/AgentRunner                       消息循环（consumeStep 消费 StreamEvent）；M4 Result 已带 totalInput/cache/interrupted
  ├─ tool/
  │     ├─ ToolExecutor 接口 + SerialToolExecutor   唯一实现；M5 ② 新增 ParallelToolExecutor（读并行/写串行/保序），接口不变
  │     ├─ Tool / ToolResult / ToolSpec      工具抽象（含 inputSchema，M8+ 结构化输出校验素材）
  │     └─ PathGuard / DangerGuard           安全边界（并行/子任务沿用，不削弱）
  ├─ permission/PermissionManager            权限判定；子任务需独立权限上下文/护栏上限（③）
  ├─ conversation/                           Message 内容块(text/toolUse/toolResult)；多 agent 历史需隔离/回填
  ├─ session/SessionStore                    JSONL（M4）；子任务会话独立落盘？
  ├─ config/AppConfig + ConfigLoader         record 加字段要同步 config.example.yml + ConfigLoaderTest（M2/M3/M4 模式）
  ├─ context/ContextCompactor                M4 双层压缩；并行/子任务后的占用统计与压缩要兼容
  └─ tui/ChatApp + TurnInterruptController   M4 中断；并行流/子任务的中断与逃生门要覆盖
```

依赖方向自上而下、无环；`ToolExecutor`/`Tool` 接口不变（并行只加实现）；M4 的 `LlmStream`（每流一个队列 + cancel/join）是 M5 并发重构的现成锚点。

## 3. 踩坑清单（新会话必看，避免重蹈）

### M1/M2/M3（摘要，详见交接-M3/M4）
1. bash 大输出死锁（>64KB 管道缓冲假超时）→ 独立线程边读边等。
2. 权限确认 raw 单键不可靠 → 「输入 a/d/s 回车确认」。
3. rm/mv/cp 路径校验防 shell 展开（`~ $ 反引号 $() ; & | < >` 直接拒绝）。
4. 会话 tool_use 参数往返：读 `argumentsJson` + `asText()`。
5. mock SSE 文本块转义：`\"` 会被吃一层 → 用 `\\"`。
6. macOS `/var↔/private/var`：PathGuard realpath 统一比较。
7. `/permissions` 命令大小写、DiffGenerator 纯换行、WriteFileTool 大文件全量读、FileHistory 双重 load、/plan 未落盘（均已修，代码含注释）。

### M4 新增（review 后修复 + 真机发现，代码已含注释）
8. **DeepSeek `/anthropic` 端点 `input_tokens` 不含缓存命中**：占用基数协议感知（`ProviderConfig.occupancyBasis`：Anthropic `input+cacheRead`、OpenAI `prompt_tokens`）；对比样例 `docs/DeepSeek-OpenAI-vs-Anthropic/`。
9. **JLine DumbTerminal 下 `Terminal.handle` 不注册信号** → 中断用 JVM 级 `Signals.register`；M5 并行流/子任务中断沿用此机制并覆盖多流。
10. **弱内存模型（Apple Silicon）**：信号线程写/主线程读无同步 → 逃生门/取消失效 → `TurnInterruptController` 跨线程字段 volatile + `exitRequested` AtomicBoolean + 逃生门粘性。M5 并行会引入更多跨线程共享，**先想清楚可见性再写**。
11. **v4-flash 在 anthropic 端点默认思考**：不传 `thinking` 也返回 thinking 块。
12. **prompt 缓存需长前缀**：短 prompt 不命中；Anthropic 端点还需显式 `cache_control` 断点。
13. **中断轮不计累计**：被取消的流拿不到 usage（StreamEnd 未到达）→ 中断轮消耗不进会话累计（设计内）。
14. **会话交替纪律（spec N3）**：中断标记 assistant「（已中断）」、压缩摘要合并进首条真实 user、不追加悬空 tool_use——保持 user/assistant 交替与双协议回填。**M5 子任务结果回填同样要守这条**。

### M5 特别留意
15. **客户端并发是硬前置**：别在修好 per-call 状态前做并行工具/子任务（数据竞争会出诡异的流错乱）。
16. **子任务上下文隔离**：独立 Conversation/权限/护栏上限，父任务拿到的是"结果摘要"而非整个子历史；回填格式要兼容双协议（参考 M4 压缩摘要合并的交替纪律）。
17. **结果保序**：并行工具执行的结果要按原调用顺序回填（Anthropic 要求同一条 assistant 消息的多个 tool_use 一次性按序回填全部 tool_result）。

## 6. 一句话提醒

M5 的核心是"从单 agent 串行升级为多 agent 并行"：**先修客户端并发安全（per-call 状态持有者，硬前置）**，再做并行工具执行（读并行/写串行/保序，ToolExecutor 接口不变），最后 Subagents/Task（独立会话/权限/护栏 + 结果回填）。安全红线与 M1–M4 能力全部沿用；子任务结果回填必须守 user/assistant 交替纪律（spec N3）与双协议兼容；并行后的跨线程可见性（volatile/原子）是重灾区，参考 M4 中断加固的教训。
