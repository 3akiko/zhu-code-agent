# zhuCodeAgent M3：文件编辑增强与 Plan Mode Spec

## 背景

- M2（Agent 循环与 Tool Use）已完成并验收通过：四文档归档于 `docs/milestones/m2/`，基线 `mvn test` 127/127 全绿。
- M2 已具备：6 内置工具 + 串行执行器 + 权限确认（a/d/s + 「总是允许」内存记忆）+ 路径边界（PathGuard）+ 危险命令兜底（DangerGuard）。
- M3 要解决的三个体验缺口（M2 spec「不做的事」明确留给 M3）：
  1. **看不见改动**：edit_file / write_file 只返回「已替换 1 处 / 已写入」摘要，用户无法确认改了什么。
  2. **不可反悔**：文件被覆盖后无法还原，没有历史与回滚能力。
  3. **不可先规划**：输入即执行，没有「先出计划、批准后执行」的环节；权限也只有「逐项确认」一档。

## 目标

- 让文件修改**看得见**：每次 write/edit 后展示变更 diff（+ 绿 / - 红），并随会话落盘。
- 让修改**可反悔**：`/undo` 撤销最近一次写操作；`/rewind` 从落盘检查点回退，跨会话有效。
- 让任务**可先规划**：`/plan <任务>` 先产出计划，用户批准后才执行（批准后写操作仍按权限模式确认）。
- 权限模式演进：`normal` / `acceptEdits` / `bypassPermissions` 三档，**M2 安全红线不削弱**（危险命令强制确认、cwd 外破坏性命令立即拒绝、禁写 `.git/` 与 `~/.zhu-code-agent/` 不变）。

## 功能需求

- **F1 diff 展示**：`edit_file` 成功后，工具结果包含该次变更的 diff：变更行前分别标 `-`（旧文本）与 `+`（新文本），可含少量上下文行；diff 超过阈值行数（config：`ui.diff_max_lines`，默认 200）截断并标注「…已截断，共 N 行」。`write_file` 成功后：新建文件返回行数/字节数概览；覆写已有文件返回与 edit_file 相同格式的 diff（同样受截断规则约束）。TUI 预览工具结果时，diff 行 `+` 绿色、`-` 红色高亮；diff 随 tool_result 落盘，会话恢复后仍可见。
- **F2 `/plan` 模式（先计划后执行）**：输入 `/plan <任务描述>` 触发单轮计划流程：
  - **计划阶段**：进入一个受约束的 agent 循环，系统提示词注入计划指令（「可用只读工具调研，完成调研后以文本输出分步执行计划并结束，不得调用写工具」）；执行器在此阶段**只放行只读工具**（read_file / grep / glob），`write_file` / `edit_file` / `bash` 一律拦截并回填「计划阶段禁止该操作」的可读错误（模型会收到并调整）；循环上限与单步空闲超时沿用 M2。
  - **计划完成**：与普通循环同一定义——模型不再调用工具（end_turn）即计划完成，模型的最终文本即计划。
  - **批准/拒绝/修改**：TUI 展示计划全文，并询问「批准执行(y) / 拒绝(d) / 输入修改意见后重新生成计划？(输入后回车)」；`y` → 同轮转入正常执行（后续写工具/bash 仍按当前权限模式确认，安全语义不变）；`d` → 丢弃计划、本轮结束，不产生任何写副作用；**其他输入视为修改意见**——意见作为一条用户消息加入会话，基于「调研结果+旧计划+意见」重新生成计划，可循环多次（每次由用户主动触发，天然可控，仍受循环护栏约束）。
  - 变更记录（2026-08-09）：批准环节由「y/d」扩展为「y / d / 任意文本修改意见 → 重新生成计划」，解决「模型在计划中提出待确认项时用户无法回应」的场景（用户批准，变更控制）。
- **F3 快照与回滚（统一检查点机制）**：
  - **快照**：每次 `write_file` / `edit_file` 执行前，将该文件当前内容存为快照（文件不存在则记录「新建」），生成一个检查点（含时间、路径、变更摘要），**落盘**于程序专属目录 `~/.zhu-code-agent/snapshots/<会话ID>/`（工具不可写、不占用工作区）；**bash 引起的工作区改动不追踪**（spec 声明此限制）。单文件超过阈值（10MB）跳过快照并在工具结果中注明「文件过大，未参与快照/回滚」。
  - **`/undo`**：回退**最近一个**检查点（快捷操作，无列表、瞬间执行）——恢复该文件本次修改前的内容；可连续撤销；与 `/rewind` 共用同一套落盘检查点，**跨会话有效**（重载会话后仍可 `/undo`）。
  - **`/rewind`**：列出检查点（时间倒序，含路径与变更摘要），选择后**撤销该检查点及之后的所有 write/edit 效果**（文件恢复到该检查点之前的状态），该检查点之后的检查点被丢弃；跨会话有效。
  - 撤销/回滚动作本身作为一条记录写回会话（用户可看到「已撤销… / 已回滚到 …」）。
  - 变更记录（2026-08-09）：撤销/回滚统一为**单一落盘检查点机制**——`/undo` 为回退最近一个检查点的快捷操作，与 `/rewind` 共用同一套检查点、均跨会话有效（用户批准，取消原「undo 仅内存」方案）。
- **F4 权限模式演进**：
  - 三档模式：`normal`（M2 现状）/ `acceptEdits` / `bypassPermissions`。
    - `acceptEdits`：`write_file` / `edit_file` 自动批准（不再逐项询问）；`bash` 仍按 normal 规则（询问/「总是允许」记忆/危险强制确认）。
    - `bypassPermissions`：`bash` 非危险命令也自动批准；**危险命令仍强制确认**；**指向 cwd 外的破坏性命令仍立即拒绝**；禁写目录规则不变。
  - 命令入口：`/permissions`（查看当前模式与「总是允许」清单）、`/permissions normal|acceptEdits|bypassPermissions`（切换模式）、`/permissions reset`（清空「总是允许」清单，模式不变）。
  - 模式仅内存、本次程序运行内有效、退出重置（与 M2 权限记忆一致）；不做 config 默认模式持久化（YAGNI）。

## 非功能需求

- **N1 技术栈**：Java 21 + Maven；不新增第三方依赖（diff 由旧内容+新内容精确生成，无需引入 diff 库）；新增配置项 `ui.diff_max_lines`（默认 200）写入 `config.example.yml`；快照大小阈值用常量（10MB）。
- **N2 可扩展性**：快照/回滚与 diff 生成作为独立模块，与工具执行链路解耦（`ToolExecutor` 接口不变，M5 并行扩展点不破坏）；diff 生成复用快照的「修改前内容」，不重复读取。
- **N3 安全**：M2 安全红线全部沿用且不削弱——危险命令强制确认、cwd 外破坏性命令立即拒绝、禁写 `.git/` 与 `~/.zhu-code-agent/`、api_key 不落盘；权限模式与「总是允许」清单不落盘；快照/检查点目录为程序专属（工具经 PathGuard 无法写入）；计划阶段写操作零副作用。
- **N4 稳定性**：diff 生成/快照/回滚失败均返回可读错误，进程不崩溃；检查点目录损坏跳过不崩溃；回滚后会话与权限状态一致。
- **N5 测试**：diff 生成、快照/回滚、权限模式、/plan 循环均有单元测试；mock LLM 端到端覆盖 /plan 批准/拒绝、三种权限模式、undo/rewind 真实文件回滚（临时工作区）；M2 的 127 个测试不回归。
- **N6 性能**：diff 与快照按需截断/限制（diff 超 `ui.diff_max_lines` 截断标注；超 10MB 文件不参与快照），控制内存、会话文件与快照目录膨胀。

## 不做的事

- 不做交互式工具结果展开/收缩（M3+，与块级/diff 渲染一起做）。
- 不做技术债：max_tokens 可配置化、多行输入（Shift+Enter）、退出时优雅关闭流线程、会话存储 JSONL 化（后置，见 docs/TODO.md）。
- 不做 bash 引起的工作区改动追踪（快照仅覆盖 write_file/edit_file，spec F3 已声明）。
- 不做权限模式/权限清单持久化（config 默认模式、落盘授权，YAGNI）。
- 不做无进展检测、Claude Code 式「暂停-继续」、并行工具执行（M5）。
- 不做 OS 级沙箱、交互式 PTY 工具/长驻进程、/goal 长任务（M5+）。
- 不做 MCP、subagents、hooks、skills、多模态。
- 不做上下文压缩、token 用量统计、prompt 缓存（M4）。

## 验收标准

- **AC1（F1）**：临时工作区真实文件：`edit_file` 成功后工具结果含 `-`/`+` diff；`write_file` 新建返回行数/字节数概览、覆写返回 diff；超长 diff 截断并标注；TUI 预览 diff 行 `+` 绿 / `-` 红（PTY 冒烟观察）；会话保存并恢复后 diff 仍可见。
- **AC2（F2）**：mock 模型场景：`/plan` 下只读工具可执行；模型尝试 write/edit/bash → 被拦截并回填可读错误、无副作用；模型 end_turn 后 TUI 展示计划并询问；`y` → 同轮继续执行（写工具按权限模式确认）；`d` → 本轮结束且临时工作区无任何写副作用；**输入修改意见 → 基于意见重新生成计划（第二次计划反映意见内容），可循环，批准后按最终计划执行**。
- **AC3（F3）**：临时工作区：edit 后 `/undo` 文件恢复原内容、连续两次 edit 可连续撤销两次；`/rewind` 列出检查点、回退到某检查点后该文件及其后所有 write/edit 效果被撤销、其后检查点被丢弃；保存并重载会话后 `/undo` 与 `/rewind` 均仍可用（跨会话）；bash 修改的文件不被 `/undo` 追踪；回滚记录写回会话可见。
- **AC4（F4）**：`acceptEdits` 下 write/edit 直接执行不再询问、bash 仍询问；`bypassPermissions` 下 bash 非危险命令直接执行、危险命令仍强制确认、指向 cwd 外的破坏性命令立即拒绝不执行；`/permissions` 可查看/切换模式；模式退出程序后重置（不落盘）。
- **AC5（N5/回归）**：`mvn test` 全绿（原 127 不回归 + M3 新增全部通过）；mock 端到端通过；真机冒烟（DeepSeek）1~2 个场景通过。
- **AC6（N3/N4）**：日志/会话 JSON/快照目录不含 api_key；工具调用写入 `~/.zhu-code-agent/snapshots/` 被 PathGuard 拒绝；损坏的检查点目录被跳过不崩溃；/plan 拒绝路径与 undo/rewind 失败路径均不崩溃、返回可读信息。
