# zhuCodeAgent M5：Agent 扩展——并行与 Subagents Spec

## 背景

- M1–M4 已完成并验收：彩色 TUI + 流式对话 + 双协议（Anthropic/OpenAI）后端；Agent 循环 + 6 内置工具 + 权限确认；文件编辑增强与 Plan Mode；上下文管理与稳定性（占用协议感知/告警/双层压缩/prompt 缓存/流式中断/会话 JSONL/max_tokens 可配置化）。基线 `mvn clean test` 215/215 全绿。
- M5 要解决的三个瓶颈（从「单 agent 串行」升级为「多 agent 并行」，P0）：
  1. **客户端并发不安全**：LLM 客户端的流累积状态（token 统计/stopReason/思考累积/工具调用累积/响应体/取消标志）是**实例字段**，同一实例并发 `stream()` 有数据竞争；取消标志永不复位、响应体单流假设。M1 靠「每轮新建实例 + UI 串行」规避，M5 做 Subagents/并行前必须重构。
  2. **工具执行串行**：一批只读工具（读文件/搜索）逐个执行，I/O 时间浪费；`ToolExecutor` 接口（一次调用 → 一批结果，顺序一致）自 M2 就预留了并行实现扩展点。
  3. **单 agent 单任务**：复杂任务只能由主 agent 串行完成，无「独立上下文的分支任务」能力。
- 术语定义（与 Claude Code / Codex 对齐）：**子任务（task）= 一个工作单元**；**子 agent（subagent）= 执行该工作单元的短暂运行实例**。父 agent 通过 `task` 工具派生子 agent，子 agent 在独立会话/权限上下文/护栏下运行，完成后把**结果摘要**回填父 agent，实例即弃（M5：不落盘、不可交互）。父一次调用多个 `task` = 并行子任务。

## 目标

- 客户端实例**可复用、可并发**：一个流一个状态对象（per-call 状态持有者），同一实例并发 `stream()` 无数据竞争，工厂按 provider 缓存复用。
- **并行工具执行**：只读工具段内并行（Java 21 虚拟线程）、写类与 bash 串行、结果严格按原调用顺序回填；`ToolExecutor` 接口不变，安全边界不削弱。
- **Subagents / Task**：父 agent 通过 `task` 工具自主派生子任务；子任务独立会话（内存）、共享父权限判定（父已批准自动放行）、三层护栏（嵌套深度/并行上限/步数上限）；结果以结构化摘要回填，支持并行子任务；级联中断。
- **不回归 M4**：占用协议感知、双层压缩、流式中断、会话 JSONL、双协议回填全部沿用。

## 功能需求

### F1 客户端并发安全重构（per-call 状态持有者，硬前置）

- F1.1 每次 `stream()` 调用持有独立的流状态对象：token 统计、stopReason、思考累积、工具调用累积、响应体引用、取消标志，全部随调用创建/销毁。
- F1.2 同一客户端实例可被并发 `stream()` 调用（多个流并存），实例不持有任何共享可变流状态；取消标志随 per-call 状态复位，实例复用不串。
- F1.3 客户端工厂按 provider 名**缓存复用**单例：主会话与子任务共享同一实例并发发起流请求。
- F1.4 重构不改变事件契约：正常结束最后必发 StreamEnd（含 usage），出错只发 Error；中断事件语义不变。

### F2 并行工具执行（读并行 / 写串行 / 保序）

- F2.1 新增并行工具执行器，`ToolExecutor` 接口不变；调用方与回填逻辑无需改动。
- F2.2 调度语义（顺序分段）：连续只读工具（读文件/搜索类）组成读段、**段内并行**；写类与 bash 一律**串行且保持原顺序**；段与段之间按原调用顺序依次执行。
- F2.3 结果严格按**原调用顺序**回填（与执行完成先后无关）。
- F2.4 单个工具失败返回 `isError=true` 结果，不拖垮同段其他调用（与串行语义一致）。
- F2.5 权限判定与串行一致：只读自动放行；写类/bash 需确认（危险命令强制确认）；并行读段内无用户交互。
- F2.6 快照/回滚语义不回归：写类串行执行，快照顺序与串行一致；只读工具不触发快照。
- F2.7 中断：Ctrl+C 中断在途并行读段与剩余调用、终止本轮；正在执行的 bash 由既有机制取消。
- F2.8 读段并行用 Java 21 **虚拟线程**（每任务一线程，不新增依赖、不引入固定线程池）。

### F3 Subagents / Task（父 agent 自主派生子任务）

- F3.1 新增 `task` 内置工具：参数为任务描述（prompt）与可选约束；父 agent 在 ReAct 循环中调用即派生一个子任务。
- F3.2 子任务 = 独立会话（内存 `Conversation`，隔离父历史，**不落盘**）；子任务复用同一 Agent 循环，仅换隔离会话。
- F3.3 子任务默认使用与父相同的工具集（含 `task`，受嵌套深度约束）与同一 provider/客户端实例（共享并发能力）。
- F3.4 权限：子任务共享父的权限判定（模式与「总是允许」记忆继承）——**父已批准过的操作子任务自动放行，不再二次审批**；未批准的写类/bash 回主 UI 统一确认并标注子任务来源；安全红线（危险命令强制确认等）不削弱。
- F3.5 护栏（均可配，默认值）：嵌套深度上限 2（父→子→孙封顶）；并行子任务上限 4；子任务步数上限 30（到达即结束并回填状态）。**深度已达上限（层 2 孙 agent）的子 agent 工具池不注册 `task` 工具**（模型不可见、从源头杜绝无效调用）；同时保留运行时兜底拒绝，任何超限调用返回可读错误。
- F3.6 结果回填：结构化摘要——状态（完成/失败/被中断）+ 最终文本摘要（截断到上限，默认 2000 字符）+ token 用量 + 错误标记；走现有 tool_result 回填通道（双协议兼容、守 user/assistant 交替纪律）；子任务完整历史不进入父上下文。**子任务失败不自动重试**：失败/被中断信息经摘要回填，由父模型自主决策是否再次调用 `task`；「被中断」与深度超限不自动重试。
- F3.7 并行子任务：父一次调用多个 `task` → 多个子 agent 并行执行（虚拟线程）。
- F3.8 中断：子任务运行中 Ctrl+C 级联中断所有在途子任务，半成品不写入会话、结果标记「被中断」回填。
- F3.9 UI：子任务运行时主终端显示折叠单行状态（如「⏳ 子任务#1: 执行中…」），完成显示「✓ 子任务#1: <摘要首行>」；子任务内部流式内容不实时滚动到主终端。
- F3.10 计数边界：父的 `max_calls_per_turn` 只统计父 agent 自身的工具调用（每次 `task` 调用计 1 次）；子任务内部工具调用不计入父计数，由子任务步数上限（F3.5）独立约束。

## 非功能需求

- **N1 技术栈**：Java 21 + Maven；并行执行用 Java 21 虚拟线程。**不新增第三方依赖**——现有 Jackson/SnakeYAML/JLine3 + JDK 标准库足以满足 M5；若实现中出现 JDK 难以承担的痛点（如需要正式日志设施），走变更控制重新评估引入成熟包（如日志框架），不擅自引入。
- **N2 安全**：M1–M4 安全红线全部沿用不削弱——危险命令强制确认、cwd 外破坏性命令立即拒绝、禁写 `.git/` 与 `~/.zhu-code-agent/`、api_key 不落日志不落盘；子任务不绕过任何权限判定。
- **N3 兼容性**：会话 JSON/JSONL 契约不破坏；双协议（anthropic tool_use ↔ openai function_call）回填不回归；子任务摘要回填保持 user/assistant 交替（spec N3 纪律）；M4 占用协议感知、压缩、中断、JSONL 能力不回归。
- **N4 稳定性**：客户端并发下无数据竞争（跨线程共享字段注意可见性，参考 M4 弱内存模型教训）；并行读单任务失败不拖垮整段；子任务失败/被拒/超限均返回可读错误、进程不崩溃。
- **N5 测试**：客户端并发、并行工具执行、子任务（派生/隔离/回填/并行/护栏/权限继承/中断）均有单元/集成测试；M4 的 215 个测试不回归。
- **N6 性能**：读段并行带来真实 I/O 重叠收益；虚拟线程启动开销极小；不引入额外锁竞争。

## 不做的事

- 不做 MCP / Hooks / Skills（M6）、OS 级沙箱（M7）。
- 不做子任务独立落盘/恢复、不可交互对象化（子任务仅内存、结果摘要化）。
- 不做子任务结果「可展开全文」（父二次查询子历史）——已记 roadmap M8+ 候选。
- 不做子任务实时流式展示/嵌套终端面板（UI 折叠单行即可）。
- 不做团队/协调器/swarm 模式（Claude Code coordinator、Codex collab 超出 M5 范围）。
- 不做 `-p` 非交互、结构化输出容错（M8+）。

## 验收标准

- **AC1（F1）**：同一客户端实例并发发起两个流：各自文本/token 用量/工具调用互不串扰、取消互不影响；实例复用后取消标志不残留；工厂缓存复用后主会话与子任务共享同一实例且并发安全（并发 mock 测试断言）。
- **AC2（F2）**：mock 双协议会话中一批 `[R1, R2, W1, R3]`：R1/R2 并行执行（可观测到重叠/耗时低于串行）、W1 串行且保持原序、结果按原调用顺序回填；单个读工具失败不拖垮同段；Ctrl+C 中断在途读段并终止本轮；写类/bash 权限确认与串行一致。
- **AC3（F3）**：父 agent 调用 `task` 工具 → 子任务在独立会话中执行（看不到父历史）→ 结构化摘要回填（含状态/摘要/token）→ 父继续循环；父一次调用两个 `task` 并行执行；嵌套深度超限被拒绝并返回可读错误；父已批准的操作子任务不二次确认；未批准写类回主 UI 确认；子任务运行中 Ctrl+C 级联中断所有在途子任务、结果标记「被中断」。
- **AC4（N2/N3/N4）**：安全红线不削弱（危险命令强制确认、禁写目录等）；双协议回填不回归；子任务摘要回填保持交替纪律；并发/并行/子任务失败路径均不崩溃、返回可读信息。
- **AC5（N5/N6）**：F1/F2/F3 的单元与集成测试齐备；M4 的 215 个测试全绿不回归；读并行场景耗时低于串行（真实多文件 mock 可观测）。
