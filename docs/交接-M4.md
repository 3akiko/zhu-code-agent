## 1. M4 要做什么（roadmap 2026-08-10 重组定义）

**M4 上下文管理与稳定性（P0）**：
- token 用量统计与展示（每轮 in/out + 会话累计 + 上限百分比）
- 接近上限告警（如 80% 提示，可配）
- 上下文自动压缩（compaction：摘要化最旧轮次 / 截断 tool_result / 丢弃历史，对标 Claude Code 的 /compact）
- prompt 缓存（Anthropic `cache_control` 断点 + OpenAI/DeepSeek `cached_tokens` 命中统计展示，降本提速）
- 流式中断（Ctrl+C 取消本次生成，半成品消息回滚）
- 非交互模式 `-p "prompt"`（一次性输出 + 退出码，供 CI / 脚本化）
- 结构化输出容错（工具参数 schema 校验 + 重试）

**顺带技术债（TODO 已标 M4 归属）**：max_tokens 可配置化（AnthropicClient 写死 8192/64000，按模型区分上限）；退出时优雅关闭流线程（与流式中断一起做：interrupt + join）；会话存储 JSONL 可选（或留 M7）。

**M4 不做**：并行工具/Subagents（M5）、MCP/Hooks/Skills（M6）、OS 沙箱（M7）。

> 主对话已澄清的机制（写进 M4 spec 时可直接用）：
> - **prompt 缓存分工**：`cache_control` 是客户端（我们）在请求里打的缓存断点（system/tools/轮次边界，Anthropic ephemeral，5 分钟窗口）；`cached_tokens` 是服务端回传的命中统计（OpenAI `prompt_tokens_details.cached_tokens` / DeepSeek `prompt_cache_hit_tokens` / Anthropic `cache_read_input_tokens`、`cache_creation_input_tokens`）；模型本身不参与。agent 循环前缀稳定，天然适合 prompt 缓存。

## 3. 踩坑清单（新会话必看，避免重蹈）

### M1/M2（见交接-M3.md，摘要）
1. **bash 大输出死锁**：输出 >64KB（管道缓冲）时先 waitFor 后读输出假超时 → 独立线程边读边等（BashTool.readOutput）。
2. **权限确认 raw 单键不可靠**：受限 PTY 下 tcsetattr 不生效 → 「输入 a/d/s 回车确认」。
3. **rm/mv/cp 路径校验防 shell 展开**：目标含 `~ $ 反引号 $() ; & | < >` 直接拒绝（DangerGuard.isSafeTarget）。
4. **会话 tool_use 参数往返**：Message.readBlock 读 `argumentsJson` + `asText()`（别用 toString/旧字段名）。
5. **Java 文本块转义**：mock SSE 里 `\"` 会被吃掉一层反斜杠 → 用 `\\"`。
6. **macOS /var↔/private/var**：PathGuard 根与候选统一 realpath 比较。
7. **JLine 单键/raw 模式**：不要依赖 raw 单键做交互；PTY 冒烟用 TTY 会话。

### M3 新增（review 后修复，代码已含注释）
8. **/permissions 命令大小写**：cmd 整体小写化后与驼峰常量比较永不匹配 → 统一小写比较（真机冒烟发现）。
9. **DiffGenerator 纯换行差异不可见**：splitLines 丢弃结尾空行 → 保留（仅增删末尾换行的 edit 也能显示 diff）。
10. **WriteFileTool 覆写大文件全量读内存**：覆写前无条件 readString 旧内容 → 10MB 上限跳过 diff（与快照上限一致）。
11. **FileHistory 快照双重全量 load**：nextId + append 各读一次 checkpoints.json → 合并为一次。
12. **/plan 各出口未 saveSession**：与 sendAndRender 对齐，出口统一落盘。

### 会话/序列化相关（M4 压缩会碰，务必小心）
13. **会话 JSON 契约**：Message/ContentBlock 序列化走 Jackson（type 判别 text/tool_use/tool_result），旧会话加载有迁移逻辑——**压缩/折叠历史不能破坏加载与双协议回填**（参考 M2「旧会话字符串 content → TextBlock 迁移」的做法）。
14. **usage 解析现状**：双客户端已把 inputTokens/outputTokens 收敛进 StreamEnd；加 cache 指标时保持「客户端解析 → 统一事件」模式，调用方不感知协议差异。

## 4. 协作约定（重要，务必遵守）

- **四文档流程**：M4 按 hdz-code-spec：S1 澄清 → spec.md → plan.md → task.md → checklist.md，每份**用户明确批准**后才进入下一步；HARD GATE：四文档全批前不写实现代码。
- **先 review 再提交**：每次开发批完成后，**先交用户 review（对照 checklist/验收报告）**，用户确认后才 `git commit`；未经确认不提交。
- **变更控制**：已批准文档（spec 等）改动须走变更控制：从受影响最上游文档改起 → 重新审批 → 级联下游；并加变更记录（日期+理由+用户批准）。
- **S1 澄清节奏**：一次一个问题（优先选择题，推荐方案放第一）；不确定就问，别替用户拍板安全/范围决策。
- **分支**：当前已在 `feature-m4-context-management`；master 保持可运行基线，M4 完成后再合并。
- **存档**：M4 完成后四文档归档 `docs/milestones/m4/` + 更新 implementation.md / CHANGELOG / roadmap 对比表与状态 / resume.md（root + 归档），并按 roadmap「里程碑收尾检查清单」9 项逐个打勾（README 尤其容易漏）。
- **resume.md 务必同步**：每个里程碑完成**以及每次重要 review 后**都要更新；当前一份"项目经历"草稿（M1–M3 已实现 + M4 上下文管理，纯文本）在用户手里，M4 完成后需把"上下文管理（prompt 缓存/自动压缩）"从规划改为已实现口径并同步到 resume。

## 6. 一句话提醒

M4 的核心是"让长会话不崩、不贵、可中断、可脚本化"：token 统计/告警/自动压缩/prompt 缓存 + 流式中断 + `-p` 非交互 + 结构化输出容错。安全红线与 M1–M3 的能力全部沿用，别在 M4 里削弱；prompt 缓存的关键是"客户端打断点 + 读 usage 度量降本"，压缩的关键是"不破坏会话 JSON 契约与双协议回填"。
