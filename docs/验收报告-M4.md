## 协议感知占用修正记录（2026-08-11，用户批准）

- **问题**：Anthropic 协议（DeepSeek `/anthropic` 端点与真实 Claude）`input_tokens` 只含未缓存部分，`cache_read_input_tokens` 单独返回；原占用口径只用 input_tokens → 占用严重低估（真机第 2 轮 input=321 + cache=1024 只显示 16%，实际 67%），告警/自动压缩在 anthropic 端点永不触发。
- **修复**：`ProviderConfig.occupancyBasis(input, cacheRead)` —— anthropic = input + cacheRead（clamp 负数），openai = input（prompt_tokens 已含缓存，不重复计）。`ChatApp.applyResult` 用它刷新 `lastInputTokens`（告警/自动压缩共用）。
- **证据**：`docs/DeepSeek-OpenAI-vs-Anthropic/`（README + 抓取样例.py + samples/ 8 组请求/响应：OpenAI 723=640+83 含缓存 / Anthropic 42+768 不含缓存；v4-flash 在 anthropic 端点不传 thinking 也返回 thinking 块；缓存需长前缀 + cache_control）。
- **回归**：`ProviderConfigTest` 5 例（anthropic 加缓存 / 无缓存不变 / openai 不重复计 / 负数 clamp）。真机 demo 确认告警与自动压缩在 anthropic 端点上按协议口径正常触发。
