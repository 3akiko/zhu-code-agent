## 2. 关键架构速查（M3 会动的部分）

```
Main → ChatApp(TUI 状态机)
  ├─ agent/AgentRunner          消息循环（替代 TurnRunner）
  │     ├─ llm/                 StreamEvent(ToolCall/TextDelta/...) + 双客户端
  │     ├─ tool/                Tool 接口 + 内置 6 工具
  │     │     ├─ PathGuard      cwd 边界（realpath 含符号链接、禁写 .git/自身目录）
  │     │     └─ DangerGuard    危险命令 + rm/rmdir/mv/cp 目标必须在工作区内

  ├─ conversation/              Message 内容块（Text/ToolUse/ToolResult）
  └─ session/SessionStore       会话落盘（tool_result 64KB 截断、旧格式迁移）
```

## 3. M2 踩坑清单（新会话必看，避免重蹈）

1. **bash 大输出死锁**：输出 >64KB（管道缓冲）时先 waitFor 后读输出会假超时 → 必须独立线程边读边等（`BashTool.readOutput` + `OUTPUT_READER`）。
2. **权限确认 raw 单键不可靠**：受限 PTY 下 tcsetattr 不生效 → 用「输入 a/d/s 回车确认」（spec F3 有变更记录）。
3. **rm/mv/cp 路径校验防 shell 展开**：目标含 `~ $ 反引号 $() ; & | < >` 直接拒绝（`DangerGuard.isSafeTarget`）。
4. **会话 tool_use 参数往返**：`Message.readBlock` 读 `argumentsJson` + `asText()`（别用 `toString()`/旧字段名）。
5. **Java 文本块转义**：mock SSE 里 `\"` 会被吃掉一层反斜杠，wire 层 JSON 会坏 → 用 `\\"`。
6. **macOS /var↔/private/var**：PathGuard 根与候选统一 realpath 比较。
7. **JLine 单键/raw 模式**：不要依赖 raw 单键做交互；PTY 冒烟用 TTY 会话。

## 4. 协作约定（重要，务必遵守）

- **四文档流程**：M3 按 hdz-code-spec：S1 澄清 → spec.md → plan.md → task.md → checklist.md，每份**用户明确批准**后才进入下一步；HARD GATE：四文档全批前不写实现代码。
- **先 review 再提交**：每次开发批完成后，**先交用户 review（对照 checklist/验收报告）**，用户确认后才 `git commit`；未经确认不提交。
- **变更控制**：已批准文档（spec 等）改动须走变更控制：从受影响最上游文档改起 → 重新审批 → 级联下游；并加变更记录（日期+理由+用户批准）。
- **S1 澄清节奏**：一次一个问题（优先选择题，推荐方案放第一）；不确定就问，别替用户拍板安全/范围决策。
- **分支**：从 `master` 切新功能分支（如 `feature-m3-plan-mode`），master 保持可运行基线。
- **存档**：M3 完成后四文档归档 `docs/milestones/m3/` + 更新 implementation.md / CHANGELOG / roadmap 对比表 / resume.md（并归档 resume）。
- **resume.md（面试简历）务必同步，重要程度等同代码**：每个里程碑完成**以及每次重要 review 后**都要更新 root 版 `docs/resume.md`，否则面试材料与代码现状脱节（例：M2 review 后测试数 119→127、安全边界扩展到 rm/mv/cp、权限记忆粒度表述都需同步）；root 版是活文档，里程碑快照归档 `docs/milestones/mN/resume.md`。
